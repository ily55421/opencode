评分模型

工程判断，不是实测

唯一的实测数据是工期与证据等级；收益分是显式权重下的工程判断，可复核、可改权重重算。单个维度 1–5 分，加权后 ×20 映射到 100 分。 这样做的理由：P0 的收益大多不是"功能有没有"，而是"出错时少付多少钱、少走多少弯路"，直接给总收入数字会假装精确。 切换下面的目标预设，象限、ROI、热力表总分、对比表会全部重算。

L1 循环失控防护 84 分 · 1.25d

唯一直接改变模型行为、同时压掉无效 token 的一项，也是 P0 里最贵的一项。

  • 收益：把 3 步死循环和 30 步正常工作分开；结果参与键，避免误伤轮询（C4 净增益）。
  • 成本：新增 fold 骨架与四类计数器，收尾步要改 runner/llm.ts，不是只改常量。
  • 风险：默认开的前提是"轮询不误伤"同 PR；否则必须默认关。
轴：step 边界证据：本轮实测

L30 + L17 cache 轴 64 / 56 分 · 1.25d

最便宜的确定性：一条字节恒等测试就能判定 C22 成立与否。

  • 收益：MCP 重连/升级不再打掉整个前缀；L17 把"前缀字节一致"变成可测断言。
  • 成本：一个递归排序纯函数 + 一个哈希断言，不需要 provider。
  • 依赖：L17 是 L4、L25、L34 的共同守门人；L30 不成立则整条 cache 轴收缩。
轴：prompt cache证据：本轮实测

L2 Plan shell 守卫 56 分 · 0.75d

当前真实存在的破坏性执行洞：plan agent 没有 deny shell。

  • 收益：把 rm -rf、git reset --hard、包管理安装挡在 plan 外。
  • 成本：纯判定函数 + 一个 execute.before 钩子，复用现有 ShellParse.scanPortable。
  • 边界：不可判定即拒绝；不引入 basename 白名单之类的安全假设。
轴：权限证据：本轮实测

L32 指令预算 62 分 · 1.5d

最大的长期 token 杠杆，但依赖 L29 的二分纯函数，且必须让裁剪可见。

  • 收益：AGENTS.md 与技能清单不再无限进 prompt；全局/项目分开核算。
  • 成本：模型在 select 阶段拿不到窗口，百分比预算要先解析模型。
  • 风险：冲突"可见但不自动择一"可能引发产品反馈；裁剪标记必须模型可见。
轴：上下文注入证据：本轮实测

L31 审批回执 48 分 · 2.5d

把"升级优先于任何 allow"从声明变成可审计，但短期 ROI 最低。

  • 收益：四分归主 + blocked ≠ failed ≠ not-run；唯一性优势第一次可被检查。
  • 成本：投影表 + 迁移 + 纯函数 builder + TUI surface；Posture 要协议加 source。
  • 边界：回执是本地记录，不是安全认证；缺数据记 not_recorded。
轴：权限证据：本轮实测

L25 cache 保活 38 分 · 1.5d

收益未测。这不是失败，是尚未付测付费；没有可比数据不许开默认。

  • 假设：审批等待、读 diff、长 shell 期间前缀被闲置，TTL 过期后下一请求全价重推。
  • 成本：空闲边界计时 + 非流式 ping + 用量新 source；不能起 daemon 线程。
  • 先决：L30 → L17；用 session-efficiency.ts 拆出真实间隙成本。
轴：prompt cache证据：待验证

L26a formatter 失败可见 47 分 · 0.5d

已核实的静默数据丢失：格式失败被日志吞掉，模型只看到原文。

  • 收益：把"写入成功但未格式化"变成模型下一轮的输入，而不是不存在的日志。
  • 成本：改 Formatter.file 返回结构 + 三个调用点各加一行提示。
  • 边界：完整的"编辑后验证回喂"仍等共识，不在本轮。
轴：工具反馈证据：本轮实测

L5 TUI 四小件 26 分 · 0.25d 剩余

剪贴板与终端标题已存在；palette 探测也已存在。只剩 stdio 捕获待验证。

  • 收益：低；主要价值是去掉清单里的伪工作项。
  • 成本：先跑一次 dev:live 验证 server 日志是否污染 stdout。
  • 结论：验证不需要就撤项，不保留"已写完但没用"的代码。
轴：TUI证据：本轮实测

口径与限制

  • 收益分不是实测。它是 1–5 分的工程判断；唯一的实测数据是工期估算与证据等级。
  • L25 的收益栏是假设。它必须先用 script/session-efficiency.ts 测出"间隙导致 TTL 过期"的成本占比，才允许谈默认值。
  • L26b 未立项。共识题（验证属于循环还是模型）没有结论前不写码；L26a 是无论如何都该修的那一小半。
  • 工期是工程日，不含 review 往返与返工。按摘要与方案里的保守估算；架构不确定性已单列在"风险"。
  • 依赖会改变实际顺序。L32 等 L29，L25 等 L30/L17，L31 与 L37 同批；ROI 排序不等于开工顺序。
  • 所有结论对应基线 81738639df。代码若已变化，先重跑方案附录 C 的复核命令。
