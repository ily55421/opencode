## 0. 贯穿纪律（每张卡片都受约束）

1. **循环/熔断状态一律 durable fold，禁止进程内 `Map`**。`doc/session-loop.md` 的 `Decisions` 已点名否决 `Map<SessionID, number>`：位置重载或重启即清空，有界重试退化成无界开销。
2. **未知必须具名**。记不到就写 `not_recorded`，不许用默认值冒充事实；`blocked ≠ failed ≠ not-run` 三分；未声明的 cache drift 不动 pin。
3. **权限层是行为护栏，不是安全边界**。不顺手加 basename 白名单、沙箱承诺之类的安全假设（对齐 `SECURITY.md` 的 No Sandbox）。
4. **不做伪装用户轮**。任何自动反馈/预算提示走已有合成注入通道（`SessionEvent.Synthetic` / notice token），不用 user 角色。
5. **动到上下文/裁剪/压缩/缓存/预算的项，落地时在 `doc/context-economics.md` 同 diff 补一节 + 一条 `Decisions`**。该文档是活文档，不被并进任何方案稿。
6. **默认值翻转或性能声称前**：先确认运行的后端 CLI 是新构建，再用 `bun script/session-efficiency.ts --title "<同一任务>" --json` 做同 prompt / 同模型 / 同变体 / 同输出量的对比。没有可比数据就不许翻默认（L25、L1 开关、L36 是这条的落点）。
7. **doc 同步是完成定义的一部分**；`bun script/doc-refs.ts` 在 `bun run lint` 里守锚点。

## 2. 梯队一：无前置、缺口被实测钉死

### L30 — MCP schema 字节确定化

**判据**：`本轮实测` `packages/core/src/tool/mcp.ts` 是 `input: (tool.inputSchema ?? { type: "object", properties: {} }) as JsonSchema.JsonSchema` 裸透传，无排序。数组顺序那一维我方已解决（`packages/core/src/tool.ts` 的 snapshot 按名排序，C21 自我更正），所以缺口精确地只在**单个 schema 内部的键序**：MCP server 重连或升级后返回语义等价、键序不同的 schema ⇒ 前缀字节即变、KV cache 全灭，而且这类 miss 无具名（要等 L34 才归因得出来）。对方形状 `对方实测`：`crates/models/src/schema_canonicalize.rs` 的 `canonicalize_schema` 递归排序 `required` / `dependentRequired` / 所有对象键。

**落点**：`tool/mcp.ts` 的 schema 接收边界，一个递归排序纯函数。**只做字节确定，不做语义折叠**（那是 L18）。

**测试**：同一 schema 的两份乱序输入产出**字节恒等**的输出。这条测试同时判定 C22 成立与否——失败即撤项（见 §6.1），不需要外部证据。

**doc**：`doc/context-economics.md` 补"schema 字节确定"一节 + 一条 `Decisions`（记 C21/C22 的分工：数组序 vs 内部键序）。

**为什么排第一**：成本最低、确定性最高，且自证真伪。

### L17 — prompt cache 确定性纪律

**判据**：`本轮实测` `packages/core/src/session/model-request.ts` 无 `Date.now` / `toISOString`；`源稿实测` `runner/llm.ts` 注释原文 "Keep tool definitions on the final Step to preserve the provider's cached prefix."。所以本项**收窄为两件事**，不是"我方完全没做"：① 建立可测断言「同一 turn 内两次请求的前缀字节必须一致」（对已组装请求做 hash 比较，**不需要 provider**）；② 核对剩余可疑源（per-request 时间注入、媒体绑定、`gatewayPolicy` 分支）。

**落点**：断言进 `packages/core/test`；可疑源在 `session/model-request.ts`、`packages/ai/src/cache-policy.ts`。

**测试**：hash 相等断言本身；一条人为注入时间戳的负例，证明断言抓得住。

**doc**：`doc/context-economics.md` 的 `Decisions`（把"同一 turn 内两次请求前缀字节必须一致"从论证升格为纪律）。

## 3. 梯队二：缺口真实，1–3 天

### L1 — 循环失控防护（P0 里最能改变行为的一项）

**目标**：模型原地打转时硬性打断，并把纠正指令挂在**那次调用**上。`runner/max-steps.ts` 的步数上限分不清"30 步正常工作"和"3 步死循环"；`runner/unfinished.ts` 判的是"没产生副作用"。`本轮实测` 相关 grep 零命中（唯一命中是插件说明文档里的英文单词 "stuck"）。

**判据**：新模块 `core/src/session/runner/loop.ts`，用 `makeLocationNode`（`packages/util/src/effect/app-node.ts`）建 Location 作用域服务。

- **窗口从 durable 历史折叠**（纪律 1）：数据源 `session.tool.success` / `session.tool.failed` 投影行，turn 边界沿用 `unfinished.ts` 已有的 `idle` marker 作用域。**不新建 durable 事件、不新建内存 Map。**
- **键 = `effectiveName` + 持久化的 input（规范化键序后 SHA-256 前 12 hex）+ 结果摘要**。结果摘要取该 tool part 的输出文本、按 `packages/util/src/token.ts` 的字符算术哈希；provider-executed 无本地输出时退化为 status。**必须用持久化副本**，否则重启后同一次调用算出不同的键。
- 匹配：窗口 25、周期 `k ∈ 1..5`、同周期连续 `R = 5`。阈值全部为模块常量，不加配置。
- **C4 是本项目最重要的净增益**：三家原文都说要"arguments **and outcomes** identical"，两家实现里键只有 `name+args`。不补必然误伤轮询。

**四类计数器（共用同一 fold 骨架，不分叉实现）**

| 类别 | 数什么 | 上限 | 现状 |
| --- | --- | --- | --- |
| ① 同键重复 | 同一 (工具, 参数, 结果) 的周期重复 | `R = 5` 触发，`LOOP_REJECT_LIMIT = 3` 收束 | **无** |
| ② 无副作用步 | 本轮没有真实副作用 | `STALL_LIMIT = 3` / `MAX_NUDGES = 10` | 已有 `unfinished.ts` |
| ③ 外部拒绝 | 同一 (工具, 参数) 被权限规则连续拒绝 | `DECLINE_LIMIT = 8`（`对方实测` goose `DEFAULT_STOP_HOOK_BLOCK_CAP`） | **无** |
| ④ 畸形产出 | 同一 turn 内模型未按格式产出的次数 | 上限必须**对用户可见** | **无**（`本轮实测` `InputFailureReason` / `failMalformedToolInput` 判定在，`malformedCount` 零命中——**判定有、计数无**） |

四类各自病因、各自文案，**共享同一条收束**：拒绝下一次工具执行 + 追加一个 `toolChoice: "none"` 的纯文本收尾步（与 `max-steps.ts` 同形）。**不新增 `DrainResult` 变体**——重跑 drain 会重复 `settleStaleCompactions` / `settleStaleToolCalls` 等入口工作（`doc/records/2026-10-todo-completion-nudge.md` 已论证）。收束**不是 session error**：错误读起来像会话坏了，真相是模型在原地打转。前进定义 = 出现未见过的键，或同键但结果变了（① 的推论）——`unfinished.ts` 的"真实副作用"在这里不够用，重复的 `edit` 也是副作用。

第③类的**归主四分**取自 `对方实测` codewhale `ApprovalDecider::{User, SessionRule, Posture, Host}`：`host`（"没人可问"）**永远不算"用户拒绝"**。这一条错了，L31 的回执写不出 `blocked ≠ failed ≠ not-run`，L3 的措辞也会指错人。

**反应形状**：命中后下一次同键调用在 `execute.before` 被拒，`Tool.Error` → 挂成 `ToolFailure`（`源稿实测` `packages/plugin/src/effect/tool.ts`「Only execute.before may fail」）。消息是 model-visible 契约 token，字面写进 topic doc：

```
Loop guard: this exact tool call (same arguments, same result) has been made N times in
a row. Repeating it will not help. Change the arguments to get new information, use a
different approach, or ask the user.
```

不做"先警告再拦截"两阶段——`execute.before` 只有放行/拒绝两种结果，两阶段等于把同一条信息发两遍（取舍进 `Decisions`）。④ 额外借 aider 的定向修复：能给 "did you mean" 候选时给候选，不要只说"重来"。

**测试**（`packages/core/test/session-runner-loop.test.ts`，用 `session-runner.test.ts` 的 `TestLLM` seam；不 `sleep`，用 `it.effect` 的 `TestClock`）：5 次同参同结果被拒且含 "Loop guard"；改参重置；不同工具互不触发；**`A B A B` 交替打断**（连击判据做不到，本项目净增益）；**同参不同结果的轮询不打断**（C4 配重）；同一被拒权限连撞 8 次收束且文案是"用户决定"不是"空转"（③、L3）；畸形产出第 N 次停止且提示语含上限数字（④）；四类计数重启后都不归零（纪律 1）；收束是 idle 不是 error；开关关时零行为变化。512 会话上限的逐出顾虑在本设计下不需要——状态从历史折叠。

**doc**：`doc/session-loop.md` 的 "Stopping, continuing, and nudging" 表加三类行；`Decisions` 记四件事（durable fold 而非内存 Map，六个来源；结果参与键且三家原文都漏；四类计数器分病因共享收束；上限必须对用户可见）。消息 token 字面保留；`CHANGELOG.md` 记默认开启那一刻。④ 的计数同时是 L7 的一个指标——**同一个数既是熔断阈值又是评测口径，不分叉**。

**开关（决策点）**：建议常量阈值 + 保留开关**默认开**，前提 `poll-is-not-a-loop` 同 PR。若拒绝 C4 只抄连击判据，默认必须关——**这两条取舍绑定，不能一半抄 cline 一半按 gemini 的默认值**。若保留开关，L1 是 L33 注册表的第一行。

### L32 — 指令预算 + 技能清单预算与冲突可见性

**判据**：`本轮实测` 两处零命中——`grep -i budget packages/core/src/instructions/ packages/core/src/session/context.ts` → 0；`grep -i "shadow|conflict|duplicate" packages/core/src/config/plugin/skill-scan.ts packages/core/src/skill/instructions.ts` → 0。含义：**AGENTS.md 类文件多大都全量进 prompt**，且**多根同名技能静默择一**（用户看不见自己被 shadow 了）。

**借三件事（`对方实测` codewhale）**：

- **预算参数**：`DEFAULT_SCOPE_BUDGET_TOKENS = 100_000` + `DEFAULT_SCOPE_BUDGET_PERCENT = 25`（各 scope 不超过可用窗口 25%）+ `DEFAULT_STATIC_PREFIX_GUARD_PERCENT = 80` + `refuse` 语义（超预算直接不发请求）。**全局与项目分开核算**，不是一个总池子。
- **裁剪必须可见**：每一次 trim / skip / refusal 都到达模型与 `/context report`，不是静默切。做成 instruction 里的一段话，不是日志行。
- **冲突不合并**：技能审计把 shadowed / duplicate / conflict **全部列出**而非"聪明择一"；`listing_budget_fraction`（默认路由窗口 5%）+ `listing_max_description_chars`（默认 400）超限即**缩短并告知**；`invocation: explicit-only` 的技能零 ambient 占用；目录矩阵 fixture 与 `BUNDLED_SKILLS` 双射测试，把「用户技能永不被静默挤掉」做成**可断言不变量**。

**落点**：预算核算在 `session/context.ts` 的指令汇集处与 `skill/instructions.ts` 的清单渲染处。裁剪算法直接用 L29 的二分纯函数，**不在这里另写一套比例阶梯**（C19）。

**测试**：超预算 refuse 不发请求；trim/skip/refusal 三态各有一条能断言"模型看见了"的用例；shadow 关系被列出而非择一；双射测试。

**doc**：**归 `doc/context-economics.md`**——它拥有 token 预算主题，但当前**完全没有"注入块预算"这一节**，这是文档缺口不只是代码缺口。

### L31 — 审批决定落盘 + 回执 builder（权限闭环最后一环）

**判据**：`本轮实测` `packages/schema/src/permission.ts` 的 `Asked` / `Replied` 均由 `ephemeral(...)` 定义；`grep -rn -i receipt packages/core/src` 零命中。`permission/saved.ts` 只持久化「always 存下的规则」，不留决定史。**升级优先于任何 allow 是我方唯一性优势，但它是安全声明、没有可审计性。**

**按 C23 走投影表路线（不动事件词汇）**。三小块，各自可独立合入：

### L25 — prompt cache 保活 ping（先量再定默认）

**判据**：`本轮实测` 我方缓存策略链齐全但**无任何主动保活**——`packages/ai/src/cache-policy.ts` 的 `applyCachePolicy`（`AUTO`、`BREAKPOINT_CAP = 4`）、`protocols/anthropic-messages.ts` 的 `cacheControl()`、`model-request.ts` 的 `promptCacheKey` 与 `cache: {ttl}`（`boundImages` 甚至专为"切图时保持前缀字节不变"写了注释）、`session/usage.ts` 按 `cache.read`/`cache.write` 计价；`grep -rn "warm_cache|keepalive"` 只命中 `packages/ai/src/route/framing.ts` 的**入站** SSE keepalive。

**为什么我方比 aider 更需要**：审批等待、用户在读 diff、shell 工具跑长任务——这些间隙里前缀被逐字复用而一次请求都不发；TTL 过期的直接后果是下一个请求**全价重推整个前缀**。这条同时打在成本与 tok/s 上。

**形状（`对方实测` aider）**：`warm_cache(chunks)` 在请求组装完成后调用，`max_tokens=1` 的**非流式** ping，消息体只取带断点的那段前缀，间隔 `5*60-5` 秒（Anthropic 5 分钟 TTL 前 5 秒），成功汇报 "Warmed N cached tokens"，`warming_pings_left` 递减到 0 停。

**两处必须改**：

1. **不起线程**。挂 `packages/core/src/session/runner` 的**空闲边界**（等待审批 / 等待下一条 inbox），不是 daemon `Timer`——我方续跑与中断语义都以 drain 为单位，异步线程会绕过 `Fiber.interruptAll` 与写前置认领。ping 必须走**同一个 `promptCacheKey` 与同一份前缀字节**（L17 的断言就是它的守门人），否则是自己把缓存打脏。
2. **记账口径先定再写码**。ping 是真实 API 调用，`doc/usage-stats.md` 的原则是"不虚构归属"，它已把 `source: "compaction"` 排除在日聚合外；保活 ping 需显式归类（建议 `source: "cache-warm"`，**计入 tokens 不计入日活**），否则用量页会出现"没人提问却花了钱"的无法解释条目。与代码同批提交。

**默认值**：aider 把它做成显式 opt-in（`--cache-prompts` 默认 `False`、`--cache-keepalive-pings` 默认 `0`），这本身是"这笔账不一定划算"的信号。**先量**：用 `script/session-efficiency.ts --json` 拆出真实会话里"间隙导致的 TTL 过期"占多少成本。**红线：没有可比数据就不许开默认。** 前置：L30——schema 字节不稳时，ping 只是反复给一个已经脏了的前缀付钱。

**测试**：ping 与主请求的 `promptCacheKey` 一致；空闲边界进入/退出时计时起止正确（`TestClock`，不 sleep）；用户中断时 ping 一起停；`cache-warm` 用量落库且被日聚合排除；关闭时零请求。**doc**：`doc/context-economics.md`（TTL 与保活归属）+ `doc/usage-stats.md`（`cache-warm` 口径）。

### L26 — 编辑后验证结果回喂（共识题，未定不写码）

**判据**：`本轮实测` 我方写工具后**只有 formatter，而且失败被主动丢掉**——`packages/core/src/formatter.ts` 把子进程 `stdin/stdout/stderr` 全设为 `"ignore"`，命令抛错走 `Effect.logError` 后 `Effect.as(undefined)`，退出码非 0 只记日志并 `return false`；调用点 `tool/plugin/edit.ts` 拿到 `false` 后**直接回读原文**——**模型收到的 diff 里没有任何"格式化失败"的痕迹**。`write.ts`、`patch.ts` 同型。可承载验证的钩子存在：`tool.hook("execute.after")`（但只有 `before` 能否绝调用）。

**借的是通道，不是 lint 本体**。aider 的对应闭环（`对方实测`）：`edited → lint_edited → auto_commit → reflected_message → 下一轮 LLM 输入`，受 `max_reflections = 3` 约束，且格式修复优先于验证。把"验证失败"变成下一次推理的输入，走我方已有的注入通道（durable 合成项或 notice token），**不能**用 `reflected_message` 那种"伪装成模型自己刚说的话"（纪律 4）。判据从最便宜的开始：formatter 失败、`tsc`/项目自带 check、patch 后语法可解析。上限复用 L1 的计数器位（病因是"验证失败"，文案与"空转"不同，故**按病因分文案、按骨架共用计数**）。

**立项前提是共识（§6.9）：验证属于循环还是属于模型？** 现在的答案偏后者（模型自己跑 shell）。本项只是补一条可选的自动反馈，不是撤掉模型侧的 shell 工具。共识未达之前不写码；若共识是"归模型"，本项收缩成「**formatter 失败不能再被静默丢掉**」这一小半（已核实的静默数据丢失，无论如何都该修）。

**doc**：`doc/session-loop.md`。**另注**：`对方实测` aider 的 `benchmark/refactor_tools.py` 用 AST 判"假重构"（目标函数仍在顶层、子节点数偏差 `< 10%`）是**评测层指标，归 L7，不进循环**。
